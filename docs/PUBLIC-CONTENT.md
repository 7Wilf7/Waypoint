# 公开内容随部署交付

本地候选基于远端核对后的 `0a62d871c3a1a8f09dfb0bbb9094c036a9689757`。尚未读取或迁移真实内容、设置线上环境变量、推送、部署、改变连接或权限。本次只验证虚构 LocalStore。

## 方案与生效时间

| 方案 | 公开目录的 Blob 读取 | 每张已准备好图片的 Blob 读取 | 撤回 |
| --- | --- | --- | --- |
| 公开文字和栅格图片随部署交付，本候选 | 0 GET / 0 list | 0 GET / 0 list | 重新构建并部署；另行处理旧部署 |
| 文字静态，图片继续现有实时 API 核验，比较过的备选 | 0 GET / 0 list | 3 新鲜 JSON GET，加可缓存的图像信息和文件 GET | 图片在下一次权限核验时拒绝；文字仍需部署 |
| 全部保持现有实时方式 | 每个保存条目一个新鲜 JSON GET，加 list 页数 | 同上 | 下一次实时读取生效；已交付副本无法收回 |

选择第一种，因为目标是减少普通公开内容的访客 Blob 读取，它不增加第二套权限目录、同步协议或存储 schema。备选方案没有在候选中实现；如果必须即时阻止图片的后续读取，应在上线前改用备选。真正要求文字与图片均实时撤回，则需要所有内容经过运行时授权，不能同时承诺直接静态资源零检查。

私有 Blob 仍是管理权威。后台的 `published=true` 在静态模式中表示“纳入下次部署”，并不证明它已经上线；`false` 表示下次部署排除。

| 后台操作 | 私有存储 | 当前公开文字和静态图片 | 旧 PDF |
| --- | --- | --- | --- |
| 新建或保存草稿 | 保存后生效 | 不进入下次静态包 | 未公开关联不得下载 |
| 修改已纳入发布的内容 | 保存后生效 | 下次成功部署切换后更新 | 使用当前关联与状态 |
| 纳入发布 | 保存后生效 | 下次成功部署切换后公开 | 当前公开关联可以下载 |
| 改为草稿或移除图片 | 保存后生效 | 下次部署排除；旧部署另行处理 | 下一次读取重新检查；撤回后拒绝 |
| 上传未关联文件 | 保持私有 | 不导出 | 不公开 |

“已送出/在途字节”及别人下载、截图、复制的内容无法远程收回。没有静默承诺永久公开，但直接静态交付必须接受按部署撤回的语义。

共享关联按记录分别判断：撤回某条记录会停用该记录的实时 PDF 链接；其它仍公开的记录若关联同一个文件，仍可访问。静态图片也只有所有公开关联都移除后，才会在下一次部署包中消失；草稿引用不会额外授予公开权限。

## 静态包与边界

`npm run build` 默认仍为 `live`，不读取 Blob。明确启用后才导出：

- `published/catalog.json`、`races.json`、`articles.json`：重新经过既有 `validateEntry` 的公开字段，保留 authored 中英文正文、标题、时间和赛事数据；不序列化原始未知字段。
- `published/media/<sha256>-preview|read|original.webp`：只处理公开条目关联的 JPEG、PNG、WebP。640×960 preview、1920 宽 read、全尺寸 quality 95 WebP；都不裁切、不放大、按 EXIF 方向转正并移除元数据。全尺寸链接明确写“查看完整尺寸”，并非原始字节下载。
- PDF 仅有类型标记，原件留在 Blob。下载要求唯一合法 `entry`、`format=pdf`、无 `size`；MIME 必须为 PDF，发送前再次核验当前公开状态与关联，不做全目录扫描。

没有复制草稿、未关联文件、原始文件名、auth 记录、环境文件、私有 Blob URL 或凭据。导出不调用 `auth()`，不写入/删除真实存储，也不生成私有变体。所有图片独立成文件，内容哈希去重；没有图片代码字符串。

单文件输入/输出上限 8 MB、输入 64M 像素、最多 256 公开条目/256 关联媒体、静态包 128 MB。损坏、缺失、不支持的关联图片或不完整双语让构建失败，不偷偷放出原文件，也不忽略内容继续上线。这些是防止失控的上限，不是已知真实数据规模。

末尾重读选中条目和媒体元数据，有变化则失败并清理临时输出。旧存储的逐条读取没有事务：末尾检查之后仍有窗口，新发布但初始没选中的记录也可能不在快照内。**正式导出开始到新部署生效前，必须暂停所有写入者和未完成保存；此候选没有自动跨部署写锁。**

API 与浏览器共享同次构建生成的模式。函数打包 `server/publication-build.json`；source/mode/lifecycle 不一致直接 503，读取次数为零。静态目录缺失或加载失败只显示重试，不回退 Blob。匿名旧 `/api/entries` 307 到对应静态 JSON；旧图片 `/media` 地址默认 404，后台 owner 预览仍实时私有。

## 缓存、旧部署与 Preview

`/published/*` 设置浏览器及下游缓存 `no-store`；页面原有的有界解码内存缓存仍保留。刷新或新访问才能获得新目录，已打开页面不会自动清空旧正文/图片。

Vercel 的静态文件会在部署存续期间保存在其交付网络中，不能把响应头当成删除部署内容的机制。移除新部署里的文件、清理缓存和限制旧部署访问是不同操作。当前生产域名切到新部署后，应核对被撤回目录项消失、旧文件路径返回 404；**旧唯一部署 URL、分支别名、仍指向旧版本的自定义域名及旧 Preview 不会因这次切换自动撤回。**

上线前要逐项列出这些入口，决定保留、重指向、限制访问或删除。部署保护范围可能覆盖 Preview 与历史生产部署，但当前项目实际设置及计划可用能力尚未核验；不得假设已有保护。删除部署会失去该部署的 instant rollback。限制访问、删除部署和连接变更都要用户明确批准；本次未执行。

新代码在 Preview 的 API/媒体路径拒绝 `live` 或 `blob` 来源；Blob 静态导出仅允许明确的 Production。虚构 `local` 快照可用于本地/fixture Preview，禁止 Production；如果 fixture Preview 的 Function 仍连接 BlobStore，API 也会 503，不能借 fixture 模式读取真实 PDF/auth。此前发布的旧 Preview 不受新代码控制，仍须审计。

依据：[静态缓存](https://vercel.com/docs/caching/cdn-cache)、[生成部署地址](https://vercel.com/docs/deployments/generated-urls)、[保护范围](https://vercel.com/docs/deployment-protection)、[删除部署](https://vercel.com/docs/deployments/managing-deployments)、[缓存响应头](https://vercel.com/docs/caching/cache-control-headers)。

## 虚构验证与读取比较

从候选根目录运行，不依赖真实环境文件：

```sh
node scripts/measure-public.mjs
WAYPOINT_PUBLIC_SOURCE=local WAYPOINT_LOCAL_DIRECTORY="$PWD/.local/static-fixture/private" npm run build
npm run check
WAYPOINT_PUBLIC_SOURCE=local WAYPOINT_LOCAL_DIRECTORY="$PWD/.local/static-fixture/private" WAYPOINT_PREVIEW_BUILD=1 WAYPOINT_PORT=4311 WAYPOINT_SESSION_SECRET=fictional-static-preview-session-secret npm run dev
```

虚构管理密码为 `fictional-waypoint-test-password`，只适用于该临时 LocalStore，不能用作生产配置。`measure-public` 只替换本仓库明确命名的 `.local/static-fixture`，证据写入忽略的 `verification/static-public/`。默认 `npm run dev` 保持原开发方式；复现静态交付须使用上面的 build preview。

样本为 35 公开条目（32 赛事、3 文章）、7 草稿、3 栅格图片、1 旧 PDF。以下是**实测 LocalStore 调用对应 BlobStore GET/list 的模型**，不是实际 Vercel 账单。图片变体已在虚构私有存储准备好；无 owner cookie、无重试。

| 一次内容访问 | 旧 GET / list | 新 GET / list | 浏览器内容/图片请求（旧→新） | 响应正文 bytes（旧→新） |
| --- | --- | --- | --- | --- |
| 首页只看首屏 | 0 / 0 | 0 / 0 | session 1→1；图片 0→0 | 54→56 |
| 首次目录 + 1 张可见 preview | 47 / 1 | 0 / 0 | 目录 1→1；图片 1→1 | 26,561→26,315 |
| 从已加载目录打开文章 | 0 / 0 | 0 / 0 | 0→0 | 0→0 |
| 打开赛事的 2 张阅读图 | 10 / 0 | 0 / 0 | 图片 2→2 | 18,396→18,396 |
| 打开完整尺寸图 | 4 / 0 | 0 / 0 | 图片 1→1 | 41,101→27,286 |
| 折叠状态赛事档案 | 42 / 1 | 0 / 0 | 目录 1→1；图片 0→0 | 17,215→17,086 |
| 旧 PDF 下载 | 4 / 0 | 4 / 0 | 文件 1→1 | 73→73 |

正文 bytes 未压缩，不含 HTTP 头、Blob list 的响应、共享 JS/CSS/字体/已有站点图片及音乐，也不等同计费传输量。浏览器实际请求与截图另见 `browser.json`。现有 400px 目录按需、240px 图片按需、两并发图片队列、解码内存复用、后台上传和旧 PDF 保存优化均保留。

此样本导出本身有 88 次 GET 模型调用（85 新鲜 JSON、3 可缓存原件）、1 list 页、0 私有写入；生成 92,719 bytes，3 图片去重为 6 文件。读取从每次访客移到每次生产构建，构建也消耗额度。

真实站点估算：保存总数 N 未检查且 N≥35；一次旧目录为 N 新鲜 JSON GET + list 页数，新目录为 0 Blob GET/list，但仍有一次静态 JSON HTTP 请求。已准备变体的每个旧图片请求有 3 新鲜 JSON GET + 2 可缓存 GET，新静态图片为零 Blob 调用、一次静态图片请求。缓存命中免 Simple Operations，`list` 是 Advanced Operations；不能把所有 GET 或 list 都等同 Simple Operations。首次生成变体的旧成本可能更高。

生产真实字节、自然访客量、缓存命中率和当前滚动用量**未测**。14,736 仅是之前的历史滚动 30 日观察基线，不是当前用量或修复后日耗率。静态交付仍消耗网站 CDN 请求和传输额度，管理/session、PDF、构建及旧部署也可能继续读取 Blob；不保证整月必然低于免费额度。计费归类依据：[Blob usage](https://vercel.com/docs/vercel-blob/usage-and-pricing)。

## 获准后的首次切换

1. 确认公开范围与撤回语义：当时 `published===true` 的合格双语文章/赛事及关联图片可进入部署包，草稿、孤立附件和 PDF 原件不进入；本次 35 是此前证据下限，正式导出应核对当前选择数。
2. 核对最新远端、实际生产部署来源、全部域名/别名/历史生产部署/Preview 和写入者，提供具体列表供批准；对旧入口限制/删除不能用笼统授权代替。
3. 关闭未完成编辑/上传并暂停所有后台/API 写入。从导出开始保持到新生产部署切换完成。保留当前代码与存储权威，任何备份都不公开 auth/凭据。
4. 经批准后，仅 Production 设置 `WAYPOINT_PUBLIC_SOURCE=blob` 和 `WAYPOINT_PUBLIC_LIFECYCLE=deployment`，继续现有私有 Blob 连接。读取权限不变，不新增付费服务。新代码构建时导出；不向 Blob 写新目录、不回写数据、不删除旧数据、不把生成快照加入 Git。
5. 对合格数量、两种正文、关联图片文件和摘要校验后完成构建/部署。构建错误立即停止；不能改回 live 继续发布来掩盖失败。生产代码推送会触发自动部署，须在授权范围和暂停写入完成后进行；若需要 PR，使用 draft 并防止意外部署真实内容。
6. 小规模核验生产目录、图片独立资源和实际响应头；检查草稿/孤立路径不可访问、退出登录管理 403、被撤回路径 404，以及未产生访客 Blob 目录读取。无需压测。
7. 按逐项批准方案处理旧入口，验证后恢复管理。以后每次公开更新/发布/撤回重复暂停写入、构建、切换和旧入口检查；保存草稿可继续日常操作，部署窗口中暂停。

## 安全回滚

快照不是管理权威，不做快照到 Blob 的回写。

静态代码回滚：暂停写入，使用待回滚代码**重新导出当前私有状态**并重新构建/部署。不能直接 promote 旧静态部署或复用旧快照，否则会重新公开已经撤回的内容。不能恢复旧存储备份覆盖当前撤回。

紧急恢复实时交付：在新构建中设 source 为 `live`、移除 lifecycle，使用仍读取当前私有权威的代码重新部署；不会恢复任何旧条目。代价是重新产生原来的访客 Blob 读取，须经用户批准。旧静态部署资源仍须单独限制或删除。

虚构测试已覆盖旧快照仍保留内容、下一次快照排除撤回、用当前权威重建的回滚继续保持撤回、导出中撤回失败无输出。真实迁移、真实 Vercel 缓存/别名限制、生产回滚和实体手机/Safari **未验证**。
