# Aevum 与个人网站的比赛关联

2026-10-01，根据本地 Aevum 源码检查。本文是实现评估，不表示已经接通生产数据。

## 当前结论

手动整理适合先开始，已经为 Waypoint 增加比赛和文章的草稿、发布、照片与证书上传。自动同步可做，复杂度中等，需要在 Aevum 一侧增加受控的展示出口。无需把个人网站变成另一个训练应用。

## 已有基础

- `products/ultreia/src/lib/db/races.js` 已有 `name`、`date`、`distance`、`category`、`ascent`、`resultSeconds` 等字段。数据由 Ultreia 拥有，按登录用户读取。
- `products/ultreia/src/components/RacesTab.jsx` 的完赛流程将目标赛事变成历史赛事：`isTarget` 设为 `false` 并填写成绩。仅到比赛日期不代表完赛，历史记录本身也不能保证存在有效成绩。
- 比赛数据层没有现成的照片、证书或“展示到个人网站”字段。通用 Aevum 导出包含其自身记录和聊天数据，不能直接当作公开赛事清单使用。
- 当前 Waypoint 通过自己的内容存储展示用户手动发布的记录，不读取 Aevum 的私有数据库。

## 后续自动同步建议

1. 在 Aevum 的赛事详情加一个明确的“展示到个人网站”选择。只有已完成、用户选择展示的比赛可以导出；不能默认公开所有历史赛事。
2. Aevum 服务端输出最小展示清单：稳定赛事 ID、名称、日期、类别、距离、爬升、成绩和更新时间。排除用户身份、精确坐标、训练明细、私人笔记及其他产品数据。
3. 网站按稳定赛事 ID 创建或更新草稿。重复同步不能新增重复记录，也不能覆盖网站补充的照片、证书、双语介绍或文章。
4. 用户在网站补充照片和证书后发布；比赛成绩修正、取消展示、删除等状态要能在下一次同步时正确处理。
5. 同步需要独立的受限服务凭据或 Aevum 推送签名，放在服务端。不得把 Supabase 管理密钥、登录会话或访问其他产品的权限放在个人网站浏览器代码里。

“完赛后立即出现在网站”可先表现为自动建立草稿，再由用户整理并发布。若要完全自动发布，应另行明确其展示范围。

## 复杂度

| 路径 | 复杂度 | 维护方式 |
| --- | --- | --- |
| 网站手动录入、上传、发布 | 低；这版已实现 | 每场比赛整理一次 |
| Aevum 导出一份专用比赛清单，网站手动导入 | 低到中；尚未实现 | 需要导出、导入与字段校验 |
| Aevum 完赛后自动建立网站草稿 | 中；尚未实现 | 需要权限、幂等、修正与撤回流程 |

公众号文章可由相同内容管理入口维护。网站保存正文和原文链接；微信公众号保留原有发布流程。当前没有连接公众号后台，亦没有自动向公众号发送文章。
